HOW TO ACTIVATE THE DAILY DISCOVERY AGENT (NO PAID API REQUIRED)

WHAT IS ALREADY INCLUDED:
- agent/monitor.py: working Python collector for official RSS/Atom items and selected website page-change detection.
- agent/source_registry.json: more than 65 named source monitors including FTC/NASA RSS starting points.
- .github/workflows/daily-discovery.yml: scheduled run every day at 09:23 UTC; manual dispatch supported.
- agent/data/discoveries.json: daily report; candidates are never automatically published.
- agent/data/approved.json: separate public listings requiring human verification/approval.
- The website's Agent board loads reports from this same folder when hosted.

OPTION A: PERSONAL OFFLINE FILE (OPTIONAL PYTHON)
1. Install Python 3.12+ if not already installed.
2. In the extracted folder, open Windows Terminal and run: python agent/monitor.py
3. Open the website -> Daily Agent -> Import Agent Report -> choose agent/data/discoveries.json.
4. Review candidates against the organizer’s original terms. Click Review & Add Listing to create a draft.
5. Confirm who, what, where, country, whether applications are open, and restrictions before setting to Program.
6. Save Backup to preserve your local editorial work.

OPTION B: EVERY DAY ON THE INTERNET — GITHUB ACTIONS + GITHUB PAGES
1. Create a GitHub account (free plan available, subject to usage limits and current policies).
2. Create a new repository and upload ALL files from the extracted folder. Hidden .github/workflows files must be included.
3. In Settings -> Pages -> Build and deployment -> Source select **GitHub Actions**. This is required for the agent to deploy status updates directly.
4. In Settings -> Actions -> General, permit Actions and allow workflow read/write permissions as appropriate.
5. Under Actions, open 'Daily Discovery Agent' -> 'Run workflow' to test once.
6. After the run, open the GitHub Pages address shown in Actions -> latest deployment, then select Daily Agent -> Load Latest Report.
7. The scheduled workflow runs each day (GitHub schedules are best-effort and may be delayed). The workflow publishes agent status twice: at scan start and at completion.
8. Review candidates and manually approve in your copy of the website. Export Approved Local Listings JSON.
9. To publish those approved records to visitors, upload the exported JSON as agent/data/approved.json in your GitHub repo, replacing the empty one. The website will read it on the next load.
10. Avoid editing the HTML file unless you wish to update the built-in 120 listings. The approved.json file extends the catalogue.

WHAT THE BOT DOES / DOES NOT DO
DOES:
- Read official feeds with relevant keyword filters.
- Watch selected original program pages for textual changes (not guaranteed to indicate new deals).
- Detect repeats, keep recent leads, preserve source names, and record scan errors.
- Generate a structured report that site can read when hosted.
- Leave customer listings under editorial control.
DOES NOT:
- Mine private employee discounts, leaked codes, or restricted membership benefits.
- Promise a promotion is active just because a web page has changed.
- Bypass paywalls, login requirements, robots protections or CAPTCHAs.
- Automatically certify the deal, post it to the public catalogue, notify users by email or monitor the entire internet.
- Directly edit customers' locally saved preferences from the cloud.

AGENT CARE AND OPERATIONS
- Inspect agent/data/discoveries.json for source errors; sources can block requests and site layouts can change.
- Add only authorized public RSS/Atom feeds and permitted official program pages to source_registry.json, following provider rules.
- Keyword filtering may miss niche programs; page-change watching can generate false positives.
- For higher frequency than daily change the cron with respect for sources' rate limits and hosting limits.
- Google/Bing ranking, legal review, partnerships, customer accounts, email push alerts and always-on publishing require additional services and ownership of the public deployment.

COUNTDOWN AND LIVE STATUS
- The countdown is to 09:23 UTC, the daily schedule target. It does not prove a run will occur on time.
- The downloaded HTML shows NOT CONNECTED; the countdown still works without internet.
- Once hosted with GitHub Actions, the workflow publishes agent/data/agent_status.json before starting each scan and again after completion.
- GREEN "Agent Running" is shown only while a recently published status reports an active scan; a run older than 20 minutes is not treated as current.
- GREEN "Agent Active" means a scan completed successfully within 48 hours and scanned at least one source. It does NOT mean it is scanning right now.
- Amber/red states show missing setup, overdue scans, source failures or unavailable status.
- The site checks the hosted status file every minute; GitHub Pages deployment/cache delay can affect visibility.
- Upload and publish the full new ZIP contents, including agent/status.py, .github/workflows/daily-discovery.yml and agent/data/agent_status.json, to enable this feature.

IMPORTANT PAGES DEPLOYMENT CORRECTION
GitHub Actions commits made with GITHUB_TOKEN do not trigger another Pages build automatically.
The included workflow therefore deploys the Pages site itself twice (running and completed), using official configure-pages/upload-pages-artifact/deploy-pages actions.
Make sure Settings -> Pages -> Source is set to GitHub Actions, not "Deploy from a branch".
Status display can be delayed by Pages deployment or caching; it expires running state after 20 minutes.
A green badge does not imply new offers have been verified or approved.
