DAILY DISCOVERY AGENT — DEPLOYMENT AND BEHAVIOR
================================================

Official hosted site: https://cristrini06-cpu.github.io/hidden-opportunity-vault/
Existing repository: https://github.com/cristrini06-cpu/hidden-opportunity-vault
Workflow file: .github/workflows/daily-discovery.yml

The workflow can be started on GitHub Actions manually and is scheduled for
09:23 UTC daily. GitHub may delay scheduled runs. GitHub Actions and Pages
need to be enabled, and Pages deployment must use the GitHub Actions source.
The existing workflow marks scanner running, records results, commits data,
then deploys the current site and report. It is not a background service on
visitors' computers.

Current source registry: 71 sources.
- Official RSS/Atom feeds are filtered for explicit, actionable applications.
- Official program page watchers detect content changes for researcher review.
- Some JS-only sites use link-only monitoring: reachable != open enrollment.
- Five carefully selected directory pages additionally surface topical links.
- All emitted candidate records are UNVERIFIED and need manual inspection.

Data files generated by successful runs:
agent/data/discoveries.json — candidates, page changes, health and errors.
agent/data/agent_status.json — scanner started/completed/failure state.
agent/data/state.json — deduplication and watcher fingerprints.
agent/data/approved.json — previous placeholder/approved export (if present).

Do NOT replace existing runtime agent/data files during normal upgrades.
The package excludes them intentionally. A clean repository can create them
during the first successful scan.

Verification before approving a candidate:
- Confirm official organizer, direct opportunity page, eligibility, geography,
  cost, benefit, expiry, application availability, and terms.
- Label invitation-only, closed, paid-trial and no-cash-benefit accurately.
- NEVER claim that an undated directory result is newly launched.
- Never automatically publish generic FTC news or page-change notices.

To run local unit tests (optional for developers):
  python -m unittest discover -s tests -v

CAUTION: The public GitHub Pages site has no server-side accounts or role-based
admin access. Browser-based 'Manage listings' changes are stored locally.
A real editorial publishing backend and authentication would be needed for
commercial multi-user administration.
